# Experimental event: 2020-12-07 C7.4

This page records the event decisions and the small workflow changes required
to test the repository on the 2020-12-07 C7.4 flare. It is a separate case
study. The 2024-05-14 configuration and `scripts/selfcal.py` remain the main
worked example and should not be replaced by this event-specific script.

## Status

Two phase-only rounds were accepted in the successful local test. The radio
images improved substantially after the target-SPW model correction described
below, and the accepted tables were transferred to a copy of the full-duration
MS. The original input MS was not modified.

The AIA grayscale and multiband contour products are still preliminary. Their
background stretch, dynamic range, contour selection, and alignment must be
reviewed before scientific or publication use.

SPWs 3–31. The full-duration output preserves all original SPWs.

The portable machine-readable decisions are in
[`config/2020-12-07-c7.4.example.json`](../config/2020-12-07-c7.4.example.json).
Copy it to a working configuration and edit its absolute `input_ms` path.

## Why a separate script is present

The test continues to use browser-based interactive `iclean`; it does not
switch back to deprecated `tclean(interactive=True)`. The event script differs
from the main 2024 script only where this older MS required different handling:

1. Each `iclean` mask is drawn from the complete configured SPW group rather
   than from one representative SPW.
2. After the original antenna selection is split into the short MS, CASA
   renumbers the retained rows. The workflow therefore operates on the
   antennas present in that short MS, while QA labels come from its ANTENNA
   table names so they still show the physical EOVSA numbers.
3. The interactive combined-SPW masks are reused, but each solve model is made
   on its target SPW alone. With the variable-channel 2020 SPWs, a combined
   multi-SPW MFS model acquired an invalid spectral coordinate and could leave
   `MODEL_DATA` empty even though the residual and mask looked valid.
4. Every nonempty target-SPW image model is explicitly predicted into
   `MODEL_DATA` with CASA `ft`, and nonzero predicted amplitudes are checked
   before `gaincal` is allowed to run.
5. Applying accepted tables to the full observation initializes
   `CORRECTED_DATA` from `DATA`, applies solutions on SPWs 3–31, and preserves
   unsolved SPWs unchanged. The final split does not discard or renumber the
   diagnostic bands.

These changes are isolated in
[`scripts/selfcal_2020_iclean.py`](../scripts/selfcal_2020_iclean.py).

## Run the 2020 workflow

Open Terminal, enter the repository, and activate either environment described
in the main README:

```bash
cd "/path/to/eovsa_selfcal_and_imaging_tutorial"
source .venv/bin/activate
```

For Conda, replace the last command with:

```bash
conda activate eovsa-selfcal
```

Check the event and make the pre-mask survey:

```bash
cp config/2020-12-07-c7.4.example.json config/2020-12-07-c7.4.json
CONFIG="$PWD/config/2020-12-07-c7.4.json"
# Edit input_ms in "$CONFIG" before continuing.
python scripts/preflight.py "$CONFIG"
python scripts/selfcal.py survey "$CONFIG"
```

Start the event-specific interactive run:

```bash
python scripts/selfcal_2020_iclean.py run "$CONFIG"
```

Draw the six combined-SPW masks once. For the accepted test, the two rounds
were phase-only and used 150, then 100, model-image iterations. Inspect the
all-SPW montage, phase plot, amplitude plot, and CSV before accepting either
round. A phase-only gain table should have amplitude one; the phase values are
angles in degrees and are not expected to equal one.

To reuse completed masks from a prior diagnostic run instead of drawing them
again:

```bash
MASK_RUN="/absolute/path/to/the/prior/run"
python scripts/selfcal_2020_iclean.py run "$CONFIG" "$MASK_RUN"
```

After accepting the short-interval calibration, apply it to a protected copy
of the full-duration MS:

```bash
RUN_DIR="/absolute/path/to/the/accepted/run"
python scripts/selfcal_2020_iclean.py apply-full "$CONFIG" "$RUN_DIR"
```

Read the confirmation text and type `APPLY` only after verifying the run path.
The outputs are:

```text
$RUN_DIR/final/short_peak.selfcal.ms
$RUN_DIR/final/full_duration.selfcal.ms
```

## QA expectations and current limitations

- All SPWs 1–40 must appear in the round montages, including poor diagnostic
  bands. Do not judge the solve solely from SPWs 32–40.
- Inspect gain coverage and phase continuity together with source compactness,
  position, sidelobes, and background structure from round 0 to rounds 1 and 2.
- Flat amplitude at one is expected because these were phase-only rounds; it
  does not by itself prove that the phase solution is good.
- Do not add an amplitude solve unless phase-only QA establishes a scientific
  need and the amplitude solutions are physically credible.
- Some combined-GHz SunCASA/CASA 6.6 MFS products can be fully masked or
  dominated by sidelobes. Use the individual-SPW comparisons for calibration
  acceptance.
- The current AIA grayscale and qlookplot-style contour products need more
  work. Preserve them as diagnostics, but do not present them as final science
  figures yet.
